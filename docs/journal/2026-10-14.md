T01 passes 9 of 9 and every PowerShell script parses. The new body builder, scope encoding and tamper regex were checked against BGL's sample data.

## Session — 15:26

**Summary:** Ran a second code review covering security, performance, correctness and style. It checked the code against BGL's public API documentation (the Postman collection behind docs.api.bgl360.com.au, which is rendered by JavaScript and can't be fetched directly), Microsoft Learn's custom connector and Power Automate guidance, and Microsoft's certified DocuSign connector. The review found 12 issues, and all were fixed.

**Discussion & decisions:**

- *Real secret in run history.* Power Automate shows action inputs in run history, so passing the real webhook secret to the validation action exposes it. Microsoft's guidance is Secure inputs/outputs plus a Key Vault-backed secret environment variable, and the README now requires both before any real BGL traffic. The same applies to the trigger, whose URL (with its `sig`) is itself a credential, and to the header Compose steps.
- *The earlier T13 fix needed correcting.* BGL doesn't document whether `PUT /sf/contacts/{id}` clears fields it isn't sent. The previous fix compared only the fields sent, so a cleared TFN would have been hidden. Decision: compare the whole record, require confirmation, and use a throwaway contact. `abn`/`acn` are deliberately sent exactly as read, because converting them to numbers (as BGL's PUT table suggests) would drop an ACN's leading zero.
- *Keep-alive depends on T05.* BGL returns `refresh_token_expires_at`. A weekly keep-alive helps only if refreshing extends that expiry, so the decision guide now branches on the T05 result instead of assuming it does.
- *Proxy target.* Neither this connector nor DocuSign's validates the forward target taken from the query string, and whether the platform signs the notification URL's query is unknown. Decision: allow-list Power Automate and Logic Apps trigger hosts in code, and add an edited-`target` check to T10 to find out empirically.
- *Trigger URL fragility.* Microsoft changed HTTP trigger URLs in November 2025 and adds a scale-unit segment from June 2026; the URLs can also exceed 255 characters. BGL signs the exact URL, so the README now warns that the registration and the variable must be updated together.
- *Confirmed correct, per Microsoft Learn:* the namespaces used are supported, the base64 OperationId handling matches Microsoft's guidance, `redirectMode: GlobalPerConnector` matches the per-connector redirect requirement, and Microsoft documents that the generic OAuth 2.0 provider sends fixed request formats, which is the premise of T03/T04. Performance risk was judged low: about 15 probe calls, and BGL doesn't count 401/429 responses against the daily limit.

**Work done:**

- **Data safety:** fixed the T13 write test as described above. Also fixed fund auto-detection, which never matched BGL's documented `{"funds":[{"fundID":…}]}` shape, so P05–P09 were always skipped.
- **Token tests:** `Get-BglToken.ps1` records `refresh_token_expires_at` before and after each refresh, whether it was extended, and `is_new_token`.
- **Proxy:** added the host allow-list (`IsAllowedTarget`).
- **File permissions:** the token file is now created as 0600 and `.secrets/` as 0700 on macOS and Linux.
- **Probe cleanup:** `Invoke-Probe` returns `{ Status, Json }` instead of the coupling through `$results[-1]`. In a related cleanup, a variable named `$error` was renamed because it would have overwritten PowerShell's built-in `$Error`.
- **Drift check:** added `Test-ConnectorSync.ps1`, an offline check that the code between `BEGIN SHARED`/`END SHARED` markers is identical in both `.csx` files and that operation lists agree across the API definition, `apiProperties.json` and both scripts. **Discussion & decisions:**

- *Round 2's proxy fix was wrong.* A host allow-list (`*.logic.azure.com`, `*.api.powerplatform.com`) doesn't restrict anything, because every tenant shares those hosts. The threat model was also overstated: editing a proxy URL only changes where requests sent to the edited copy go, while BGL keeps calling the registered URL. Decision: pin the target to a `ProxyTargetPrefix` constant (Flow B's trigger URL up to the `?`). The old lesson was marked superseded, not deleted, and a corrected lesson was added.
- *Deploy-time constants in a public repo.* `ProxyTargetPrefix` and `SpikeTestSecret` are edited in place for T09/T10. `Test-ConnectorSync.ps1` now fails while either is set, unless `-AllowDeployValues` is passed, so a careless commit can't publish a trigger URL or a test secret.
- *Sync check gap with real consequences.* If a `/spike/*` operation is missing from `scriptOperations`, the platform forwards that call, with its secret and the user's BGL token, to BGL. The check now catches that, and checks that each operation has a `case`.
- *T05 can't currently answer the keep-alive question.* BGL's documented refresh response has no `refresh_token_expires_at`, so T05 now reports Extended / NotExtended / Unknown with the difference in seconds, waiting 2 s first because the field is in whole seconds. The decision guide says not to choose a keep-alive on "Unknown"; it's now open question 3 for BGL.
- *T13 must normalise values before echoing them back.* BGL's own examples return `state: "VICTORIA"` (PUT accepts only the 8 codes), and BGL's GET and PUT date formats contradict each other. The PUT body now maps states and reformats dates, sends only the fields allowed for the contact's type, and is encoded as UTF-8 bytes, because PowerShell before 7.4 didn't default to UTF-8. Changes are reported with before and after values, and an `addressId`-only change is flagged as harmless.
- *Other false-result risks removed:*
  - T14 dates are now `yyyy-MM-dd'T'HH:mm:ss'Z'` (BGL's documented `updatedAfter` format).
  - `stackOwner`/`publisher` were removed, because paconn can't update a connector with `stackOwner`, which could have faked a T09 failure.
  - `-BodyStyle Bgl` reproduces BGL's newline body layout, and T11 now needs both styles to verify.
  - T05 starts from the newest token.
  - The compile check makes the undocumented stubs available only to the proxy variant (`PROXY_VARIANT`).
- *Diminishing returns.* Round 4 found nothing above low on security, and confirmed every round-3 fix. Further code review has less value than running the spike against BGL staging.
