# Harness scripts that call live BGL

These need a BGL app client ID/secret plus an interactive browser consent. Don't run them unless the user asks (see the root `CLAUDE.md` for the safety rules around writes).

- `Get-BglToken.ps1 -ClientId <id> [-TestAllStyles] [-ManualCode]` (T02/T03/T05): Authorization Code flow on `127.0.0.1:8765`, then tries four token-request styles (`BglDocumented`, `FormBody`, `FormBodyWithScope`, `FormBodyBasicAuth`).
- `Invoke-BglProbe.ps1 [-WriteTestContactId <id>] [-FinancialYear <yyyy>]` (T06/T13–T15): uses the saved token (refuses to run once it has expired) and makes about 15 calls. `Invoke-Probe` records each call and returns `{ Status, Json }`. The write test asks for confirmation (`-Confirm:$false` skips it). It builds its PUT body from the fields BGL's PUT table allows for the contact's `contactType` (`ConvertTo-BglContactUpdate`): full state names become the codes PUT accepts (`ConvertTo-BglStateCode`) and dates are reformatted to PUT's formats. It sends the body as UTF-8 bytes, then compares the *whole* record before and after, ignoring `entityRelationships` order (`Compare-BglRecord`). `Compare-BglRecord` reports each changed field with before and after values, and flags a change to `address.addressId` alone as harmless.
- `Send-BglTestWebhook.ps1 -Url <url> -Secret spike-test-secret -ClientCode spike [-HeaderName X-BGL-Authorization] [-Tamper All] [-BodyStyle Bgl]`: webhook simulator. Against a Power Automate trigger, `-HeaderName` is required: the trigger returns 401 `DirectApiRequestHasMoreThanOneAuthorization` for any request with both its `sig` and an `Authorization` header.
